# Grader fixtures

Generated by `python3 -I -B task1/assessment/fixtures/make_fixtures.py`. Do not edit the generated
files by hand: change the generator, rerun it, then rerun the tests. `tests/test_contracts.py`
fails when the files on disk differ from what the generator writes.

| Path | What it is |
|---|---|
| `world.json` | The fake services `tests/fakes.py` serves: the VIOS sensor list and timelines, RT-Embed's vectors for four queries, and the Elasticsearch documents (`mdx-raw-2025-01-01`, `mdx-embed-filtered-2025-01-01` and one `default_<file id>` caption index). It also holds course-prep's registry of the four search clips, which `tests/conftest.py` writes as `search_sources.json`. Sensor and file ids are made-up UUIDs; the search clips' durations come from the grader's ground truth. |
| `answer_key.json` | A multiple-choice key in the production format. Its letters are made up on purpose, so the tests never depend on the real `grader/answer_keys/part1.json`. |
| `pass/answers.json` | An `answers.json` that passes every check against `world.json`. |
| `cases/<name>/` | One variant each: `answers.json` (absent in `no_answers_file`) and `expect.json` = `{"passed", "fails", "services", "note"}`. `passed` is the marker's overall flag; `fails` lists exactly the check ids that fail; `services` is `up` or `down`. |

The story, in short. `rain_check.mp4` is uploaded and VIOS lists it as `rain_check_1`. RT-CV wrote
12 frame records for the stem, and car is the most frequent type. The index also holds traps that
only a correct query avoids: `normal_eval` frames with more bicycles than the clip has cars, the
same frame ids 0.6 s later, and an object that looks exactly like track 7; and `rain_checkpoint`
frames that a prefix match would count. Track 7 drifts slowly, so its nearest object in another
frame is itself one frame later. Object 21 in frame 6 is a twin of track 9 as seen in frame 3, so a
search from frame 3 ranks object 21 first.

For T5, searching the four search clips for "two cars collide at a crossing" returns `rain_eval`
20 to 25 s first, inside the labelled collision at 19.21 to 43.75 s, and `normal_eval` 45 to 50 s
second. `traffic_short` and the learner's own `rain_check` match that query even better, so a search
without the four-clip filter goes wrong. "a car drives through heavy rain" returns `rain_eval` 55 to
60 s, which shows no labelled collision. "a crash on a wet road" returns `rain_eval` 15 to 20 s,
which touches the collision, and "a collision on a sunny day" returns `normal_eval` 45 to 50 s. For
T7, 4,200 ms per chunk gives 8,640 requests and 36,288 s of RT-VLM time per camera per day.
